# ADR 0004: Soft-delete — где применяется

## Контекст
В схеме БД есть soft-delete для пользователей и карточек. 
Для аналитических таблиц (`card_stats`, `bucket_stats`, `user_daily_stats`, 
`email_verifications`) soft-delete отсутствует.

## Решение
- **Soft-delete** (`deleted_at`): `users`, `decks`, `cards`. 
  Данные остаются в БД, но скрыты из приложения.
- **Физическое удаление**: `card_stats`, `bucket_stats`, 
  `user_daily_stats`, `email_verifications`. 
  При удалении родителя строки удаляются, агрегаты пересчитываются.
- **Архивные таблицы**: `deleted_cards`, `deleted_users` — 
  для аудита и возможного восстановления в будущем.
- **Восстановление из soft-delete**: не входит в MVP.

## Обоснование
- Аналитические таблицы не нуждаются в soft-delete — 
  это создаст мусор и усложнит агрегацию.
- Архивные таблицы хранят снимок на момент удаления — этого достаточно.
- Восстановление — функция Волны 2.

## Последствия
- Восстановление удалённых данных в MVP невозможно.
- При росте — можно добавить API восстановления из архивных таблиц.
