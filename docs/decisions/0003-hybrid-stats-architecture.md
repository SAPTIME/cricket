# ADR 0003: Архитектура для роста 100 → 100 000

## Контекст
Старт на 100–1000 пользователей, цель — рост.
Доработки не должны ломать старый код.

## Решение
- Stateless FastAPI — состояние в Redis/Postgres.
- Абстракция репозиториев — переезд на ClickHouse/шардирование
  без правки кода.
- Партиционирование `events`/`page_views`/`card_session_history`
  с первого дня.
- Конфиг через `.env` — переключение реализаций без правки кода.
- Event bus как абстракция — сейчас Postgres, потом Kafka/Redis Streams.

## Обоснование
- При росте 100 → 1000 → 10000 мы добавляем инструменты, не переписываем.
- Партиционирование сразу избавляет от болезненной миграции позже.

## Последствия
- На старте чуть больше кода, чем «в лоб».
- При росте — только добавления.
